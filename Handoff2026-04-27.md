## 3. Implementation State (How)

Module/component responsibilities:

- `src/cam_rag/rag`: domain-neutral contracts and pipeline pieces
  (`README.md:L26-L33 @ main#70d09ea (2026-04-26)`).
- `src/cam_rag/methodologies`: repofrax-derived family retrieval
  (`README.md:L28-L30 @ main#70d09ea (2026-04-26)`).
- `src/cam_rag/documents`: ingestion, parsing, chunking, metadata
  (`README.md:L30-L31 @ main#70d09ea (2026-04-26)`).
- `src/cam_rag/retrieval`: dense, sparse, fusion, PRF, HyDE, reranking target
  area (`README.md:L31-L32 @ main#70d09ea (2026-04-26)`).
- `src/cam_rag/verification`: grounding, citations, confidence, receipts
  (`README.md:L32-L33 @ main#70d09ea (2026-04-26)`).
- `apps/ragamuffin`: document-folder app using `cam_rag`
  (`README.md:L34-L36 @ main#70d09ea (2026-04-26)`).

Current strategy and boundaries:

- Platform API accepts already-loaded documents and produces retrieval-only
  answers (`src/cam_rag/query.py:L16-L37 @ main#70d09ea (2026-04-26)`).
- Folder query path is intentionally generation-free and preserves the public
  shape for later dense search, RRF, reranking, and synthesis improvements
  (`src/cam_rag/query.py:L47-L52 @ main#70d09ea (2026-04-26)`).
- Ragamuffin owns clinical defaults and document-folder UX while platform
  behavior comes from `cam_rag` (`apps/ragamuffin/ragamuffin_app/app.py:L1-L5 @ main#70d09ea (2026-04-26)`).
- Ragamuffin should not own duplicate dense retrieval, BM25, RRF, confidence,
  grounding, citations, or graph expansion logic (`apps/ragamuffin/README.md:L18-L28 @ main#70d09ea (2026-04-26)`).

Dependency graph:

```text
apps/ragamuffin
  -> cam_rag.rag spec/models
  -> cam_rag.documents read/chunk/parse
  -> cam_rag.query
      -> cam_rag.retrieval sparse+dense+RRF+query expansion
      -> cam_rag.verification confidence+grounding
      -> cam_rag.evaluation for golden-question reports
benchmarks/mteb
  -> cam_rag.retrieval.EmbeddingBackend
  -> optional mteb + sentence-transformers
```
